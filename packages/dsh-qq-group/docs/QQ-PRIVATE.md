# QQ 私聊接入

私聊和群聊是**同一套行为、两份数据**。这份文档写清楚怎么用、数据存在哪、边界在哪。

## 一、加人 / 删人

和加群完全一样：**先加进列表，才会理**。

- 面板：「QQ 群聊（独立插件）」页签顶部 —— 左栏是群号，右栏是「QQ 号 → 添加私聊」
- 配置：`$DSH_HOME/dsh-qq-group/qq.json` 的 `privates`

```json
{
  "privates": {
    "<你的QQ号>": { "enabled": true, "name": "主人" }
  },
  "defaultPrivate": { "enabled": false }
}
```

两条规则：

1. **没列在 `privates` 里的人，私聊一律不回**（也不记账，不产生记忆）。跟「没列的群不接」一致。
2. **主人是例外**：`ownerQq` 那个号即使不在 `privates` 里也能聊，因为他要能发指令。

## 二、数据完全独立

每个会话在存储里有一个 key：

| 会话 | key | 例子 |
|---|---|---|
| 群 | 群号 | `809773499` |
| 私聊 | `p:` + QQ 号 | `p:<你的QQ号>` |

这个前缀不是装饰。记忆、画像、心情、日记全都只认一个字符串 key，
如果私聊直接用 QQ 号，那么「群号 809773499」和「QQ 号 809773499」会撞在一起——
群聊记忆会串进私聊，画像会互相覆盖。加了前缀，两个空间永远不相交。

受影响的文件（都各存一份，互不影响）：

| 文件 | 私聊怎么存 |
|---|---|
| `qq-memory.json` | `groups["p:<你的QQ号>"]`（上下文） |
| `memory-v3.json` | 同上（长期记忆） |
| `profiles.json` | 同上（熟识度 / 好感度） |
| `moods.json` | 同上（心情） |
| `diary.json` | 每条有 `groupId: "p:<你的QQ号>"` |

**同一份人设**（`persona.json`），但**提示词规则不同**：群里要短、别刷屏；
私聊是一对一，可以长一点、可以接着上一条说、可以更亲近。

## 三、私聊默认值和群聊不一样

私聊是 `defaultPrivatePolicy()`，不是群聊默认值。差异是刻意的：

| 项 | 群聊默认 | 私聊默认 | 为什么 |
|---|---|---|---|
| 冷场主动开口 | 开 | **关** | 群里突然说话叫热闹，私聊里突然发消息叫惊悚 |
| 冷却 | 45 秒 | **0** | 一对一本来就能连聊 |
| 10 分钟额度 | 6 条 | **不限** | 同上 |
| 语音概率 | 25% | **15%** | 私聊里突然发语音容易吓人 |

想让她私聊时主动找主人说话，就在该人的策略里把 `proactive.enabled` 打开——
这是显式选择，不是默认行为。

## 四、主人私聊的双重身份

主人私聊时，**先当指令解析，不是指令就当普通聊天**：

- `状态` / `群列表` / `暂停 <号>` / `恢复 <号>` / `说 <号> 内容` / `唱 <号> [歌名]` / `静音` / `取消静音`
- 其他任何话（"今天好累"、"帮我看看这个"）→ 正常聊天

之前只会解析指令，主人说「今天好累」会被回一句「没听懂这条指令」——那不像人。
现在指令命中就执行，没命中就聊天。

`暂停`/`说` 这类指令里的号码，会先查群表、再查私聊表，两边都没有就明确报错，
不会默默发到一个不存在的会话。

## 五、验证清单（联调时按顺序走）

1. 启动 NapCat 并登录小号（`C:\<工作目录>\start-napcat.bat`，需要扫码）
2. DSH 面板 → QQ 插件 → 点「启动」
3. 用**另一个号**（不在列表里）私聊她 → 应该**完全不回**，日志里是 `忽略未授权私聊`
4. 把那个号加进 `privates`，再私聊 → 应该回
5. 检查数据是否分开：
   - `profiles.json` 里出现 `p:<那个号>` 这一段，而群的画像没有变化
   - `diary.json` 里新条目 `groupId` 是 `p:<那个号>`
   - `qq-memory.json` 里 `groups["p:<那个号>"]` 有上下文，群里那段没被写脏
6. 主人号私聊发「状态」→ 应回连接/统计；发「今天好累」→ 应正常聊天，不是「没听懂指令」

## 六、还没做 / 边界

- **红包、转账、外卖、QQ 小程序**：这次没做。它们不是「接一条消息」这个层面的功能，
  需要协议层支持（红包领取）或平台授权（外卖 API 不对个人开放），得单独评估。
- **群文件检索**（`get_group_root_files`）在私聊里不适用，会自动跳过。
- **主动开口**在私聊里默认关闭；打开后行为与群聊一致（含夜间免打扰、冷却、每日上限）。
